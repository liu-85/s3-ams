## 二、微动电阻编码

每个料盘位两只微动，**合占 1 个 ADC 脚**，靠分压区分三种状态：

```
      3.3V
        │
     [内部上拉 ~45k]
        │
        ├────────────── GPIO (ADC)
        │
        ├── 开始位微动(NO) ──[4.7k]──┐
        │                            │
        └── 停止位微动(NC) ──[10k ]──┘
                                     │
                                    GND
```

### 三档判定（`filament_sensor.cpp:203`）

| ADC 电压 | 含义 | 动作 |
|---|---|---|
| `< 350mV` | **悬空/无信号** | 视为无效，跳过 |
| `350 ~ 433mV` | **开始位压下** | 缓冲器空 → 补料 |
| `433 ~ 1050mV` | **中间档** | 保持上一决策 |
| `> 1050mV` | **停止位顶开** | 缓冲器满 → 停料 |

> ⚠️ **350mV 门限是必须的**。微动没接或悬空时 ADC 读 **~371mV** 噪声，
> 正好落在 350~433 之间，不加门限会持续误判"开始位压下" → 一直补料。
> 这是 v1.1.0 修的问题。

### 为什么阈值要实测标定

理想分压大致是：两只都不动 ≈ 几百 mV（走 10k 支路）、开始位压下 ≈ 更低（4.7k 并联进来）、
停止位顶开（NC 断开）≈ 接近 3.3V。但**具体数值对不上理论计算**，因为：

- ESP32-S3 内部上拉实际值离散（标称 45k，实测 30~60k）
- 微动接触电阻、PCB 走线阻抗
- 3.3V 实际轨压

所以 `433 / 1050 / 350` 是**实测标定值**，以 `board_pins.h` 常量为准。
换板子或换微动型号要重新标定——Web「微动开关」卡片能看每路实时 mV。

## 二之二、临时直连微动模式（v1.1.14，电阻编码微动未到货时用）

4.7K/10K 那套电阻编码微动没到货时，可以用 **8 只普通微动**直接接原来的 8 个
传感器 IO，固件用 `digitalRead` 读。开关在 `src/filament_sensor.h`：

```cpp
#define SENSOR_TEMP_DIGITAL      1   /* 1=临时直连；0=正式电阻编码 */
#define SENSOR_TEMP_ACTIVE_LOW   1   /* 1=微动接 GND，压下为低电平 */
```

### 接线表（★ GPIO 不是连续的 0..7，沿用正式模式引脚表）

| 通道 | 开始送料微动 | GPIO | 停止送料微动 | GPIO |
|:---:|:---:|:---:|:---:|:---:|
| 1 | 微动 1 | **GPIO1** | 微动 5 | **GPIO10** |
| 2 | 微动 2 | **GPIO2** | 微动 6 | **GPIO11** |
| 3 | 微动 3 | **GPIO9** | 微动 7 | **GPIO12** |
| 4 | 微动 4 | **GPIO8** | 微动 8 | **GPIO13** |

```
微动 COM ── GPIO（上表）
微动 NO  ── GND
```

内部上拉已开，**不用外接电阻**。配对规则：**通道 c 的开始位 = 微动 c，停止位 = 微动 c+4**。

### 动作语义

| 微动 | 压下 → 固件动作 |
|---|---|
| 微动 1~4（开始位） | 吸合该通道离合 + 电机进料 |
| 微动 5~8（停止位） | 停电机 + 释放离合 |

两只都松开 = 中间态，保持上一决策，超时 `BUFFER_FEED_TIMEOUT_MS` 后自动停。

### 两个注意点

1. **为什么用 digitalRead**：`GPIO11/12/13` 属 **ADC2**，WiFi 开着时 ADC 读不到
   （正式模式下 6/7/8 路"降级"就是这个原因）。`digitalRead` 不受 ADC2 限制，
   所以测试全程开着 WiFi 也没问题。

2. **后 4 个通道被禁用**：`GPIO10~13` 已被当成通道 1~4 的停止位用掉，
   所以 `s_enabled_mask` 只留低 4 位，`sensor_channel_enabled(4..7)` 返回 false。
   本版**只能测 4 个通道**。

### 切回正式模式

```cpp
#define SENSOR_TEMP_DIGITAL   0
```

重编译烧写，`sensor_adc_init()` 自动接管，8 通道全部恢复，接线按上面第一节的分压图。
`SENSOR_TEMP_DIGITAL` 是**唯一开关**，不要去注释 `sensor_poll_digital()`。

## 三、电机与电流采样

| 项 | 值 |
|---|---|
| 驱动 | AT8236（H 桥，PWM + 方向） |
| PWM | 20kHz，`motor_pct` 0~100 |
| 启动阈值 | **≥80%** 才能可靠起转（低于这个数电机可能只是嗡一下） |
| ISEN | GPIO3，采样电阻 **200mΩ** |
| 采样周期 | 10ms，IIR 平滑 + 1 秒峰值窗 |
| 堵转保护 | `stall_ma` 默认 **0 = 只显示不保护**，需实测后填 |

### 堵转标定步骤

1. Web「手动点动」→ 选通道 → 占空比 100% → 点动 2 秒，读**正常送料电流**
2. 人为堵住料盘（或夹住耗材）再点动，读**堵转电流**
3. 取两者中间值填进「电机电流采样」卡片 → 保存
4. 观察是否误跳闸；误跳就把 `stall_ms` 调大

## 四、离合

- 8 路，ULN2803 反相驱动，**高电平吸合**
- 吸合需要时间，所以固件里是**异步状态机**：请求 → 等 → 完成才给电机
- `s_pending_clutch` **只有一个槽**，后来的请求会覆盖前面的
  → 这是"退料被缓冲逻辑打断"的根源，v1.1.12 用优先级规避

### 离合断开 ≠ 耗材自由

这是最容易误解的一点：

```
电机 ──[离合]── 主动轮 ──╲
                          ╲── 耗材 ──> 挤出机
                   压轮 ──╱
```

**离合只断开"电机 ↔ 主动轮"，压轮始终压着耗材。**
所以停料时耗材仍被齿轮组反向拽住，打印时挤出机会觉得"拉不动"。
→ 这就是必须做「跟随送料」的机械原因。

## 五、接线注意

1. **共地**：485 的 GND 必须和打印机共地，否则丢帧率很高
2. **终端电阻**：长线（>1m）建议 120Ω
3. **DE 上电默认拉低**（接收态），固件 `BambuBus_UART_Init()` 里已做
4. **电机和 485 分开走线**，PWM 干扰会让 485 误码
5. **离合续流二极管**：ULN2803 内部有，外接电磁阀不要再并
6. **不要热插拔 485**，DE 悬空时总线状态不确定

## 六、上电自检

Web「上电诊断」卡片会显示复位原因和启动阶段。
如果出现「接上负载就一直重启」，看这里：

| 现象 | 可能原因 |
|---|---|
| 复位原因 = `RTCWDT_RTC_RESET` 循环 | 固件头标了 PSRAM / QIO，与芯片不符 |
| `TG0WDT_SYS_RESET` | 主循环卡住（TWDT 10s） |
| `TG1WDT_SYS_RESET` | 同上，另一核 |
| 启动阶段停在 `motor_init` | 电机电源短路或电流过大 |
| 启动阶段停在 `BambuBus_init` | 485 收发器异常 |
