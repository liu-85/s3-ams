# 485 / BambuBus 协议笔记

本文只写**这份固件实际用到的那部分**，以及现场抓包得到的结论。
上游实现见 `src/BambuBus.cpp`，与 Tianshu 基本逐行一致。

---

## 一、物理层

| 项 | 值 |
|---|---|
| 波特率 | 1 228 800，8E1 |
| 引脚 | TX=GPIO14，RX=GPIO48，DE=GPIO39 |
| 收 | 主循环轮询 `RS485.available()`，**不是中断** |
| 发 | `send_uart()` 拉高 DE → 写 → 等发送完 → 拉低 DE |

> 因为是轮询收，**主循环任何阻塞超过约 400ms 就会丢帧**
> （`bus485_raw` 只有 32 帧，设备忙时 60~90 帧/秒）。

## 二、帧结构

### 2.1 两种帧头

解析器（`RX_IRQ`）按第 2 个字节的最高位判断：

```
byte0 = 0x3D

byte1 & 0x80 != 0  → 短头（绝大多数）
     [0] 3D  [1] flag  [2] len  [3] crc8  [4] type  ...  [len-2..len-1] crc16

byte1 & 0x80 == 0  → 长头（少数控制包）
     [0] 3D  [1] flag  [2] ?  [3] ?  [4] len  [5] ?  [6] crc8  [7] type  ...
```

- `crc8` 只覆盖 `0x3D` + `flag`（短头时是前 3 字节）
- `crc16` 覆盖除最后 2 字节外的全部
- `len` 是**整帧字节数**（含 CRC16）

### 2.2 包类型（`type`）

| type | 名称 | 方向 | 说明 |
|---|---|---|---|
| `0x03` | Cxx | 打印机→AMS | **只读**：读运动信息，不改状态 |
| `0x04` | Dxx | 双向 | **读/改运动状态**，状态机由它驱动 |
| `0x05` | — | 打印机→AMS | 长包：设置耗材类型 |
| `0x06` | Fxx | 打印机→AMS | 在线检测 |
| `0x07` | — | 打印机→AMS | 心跳 / MC 在线 / 版本 |

> ⚠️ **最容易读错的地方**：`0x03` 和 `0x04` 的字段位置**不一样**。
> `0x03`（Cxx）的 `motion` 在 `b[8]`，`0x04`（Dxx）的在 `b[7]`。
> 混着解会读出一堆假状态。`tools/mon485.ps1` 的 `Decode-Frame` 只解 `type=0x04`。

### 2.3 Dxx 请求（打印机 → AMS）字段

短头 13 字节，例：

```
3D C5 0D F1 04 00 03 00 03 FF 00 31 80
```

| 索引 | hex 偏移 | 字段 | 本例 |
|---|---|---|---|
| 0 | 0-1 | 帧头 | `3D` |
| 1 | 2-3 | flag | `C5` |
| 2 | 4-5 | len | `0D` = 13 |
| 3 | 6-7 | crc8 | `F1` |
| 4 | 8-9 | **type** | `04` = Dxx |
| 5 | 10-11 | **ams** | `00` |
| 6 | 12-13 | **statu** | `03` |
| 7 | 14-15 | **motion** | `00` |
| 8 | 16-17 | 保留 | `03` |
| 9 | 18-19 | **read** | `FF` |
| 10 | 20-21 | 保留 | `00` |
| 11-12 | 22-25 | crc16 | `3180` |

代码里就是 `AMS_num = buf[5]; statu = buf[6]; motion = buf[7]; read = buf[9];`

## 三、状态码表（现场实测）

`statu` 是**标志位组合**，不是枚举值：

| statu | 位含义 | 出现频率（一次进料抓包） |
|---|---|---|
| `0x01` | 停止广播 | 1259 帧（**最多**） |
| `0x03` | bit0+bit1 = 送/退料 | 常见 |
| `0x07` | 0x01\|0x02\|0x04 | 3 帧（极少） |
| `0x0F` | 0x07\|**0x08** = 正在使用 | 123 + 33 帧 |

> **`0x0F` 才是这台打印机的"使用中"**。整份日志里 `0x07/0x7F` 一帧都没有。
> v1.1.12 之前只认 `0x07`，导致状态永远卡在 `before_on_use`。

### 3.1 状态判定

| statu | motion | 含义 | 内部状态 |
|---|---|---|---|
| `0x03` | `0x00` | **送料** | `send_out` |
| `0x09` | `0xA5` | **准备使用**（打印机已咬住） | `before_on_use` |
| `0x07`/`0x0F` | `0x7F`/`0xFF` | **使用中**（打印） | `on_use` |
| `0x07`/`0x0F` | `0x00` | **暂停** | `stop_on_use` |
| `0x09` | `0x3F` | **准备退料** | `before_pull_back` |
| `0x03` | `0x00` + `read=0xFF` | **退料** | `pull_back` |
| `0x01` | 任意 | 停止广播 | 清 idle（打印中除外） |
| `0x00` | 任意 | 复位/取消 | 清全部 |

### 3.2 前置条件（`allow_*`）

```cpp
loaded     = get_loaded_filament(ams);          // now_filament_num 对应的通道
allow_any  = (loaded == 0xFF) || (loaded == ch); // 没占用 或 就是自己
allow_stop = (loaded == ch);                     // 必须是自己
```

| 状态 | 需要 |
|---|---|
| `send_out` | 无条件 |
| `before_on_use` / `on_use` | `allow_any` |
| `stop_on_use` / `before_pull_back` | **`allow_stop`** |

> `now_filament_num` 一旦被错误清成 `0xFF`，`allow_stop` 恒 false，
> **退料全部被拒**。这是 v1.1.12 修的核心连锁。

## 四、Dxx 应答（AMS → 打印机）

固定 60 字节（`Dxx_res[]`）：

| 索引 | 字段 | 说明 |
|---|---|---|
| 1 | flag | `0xC0 \| (package_num << 3)` |
| 5 | ams | AMS 编号 |
| 9 | 在线掩码 | bit0~3 = 通道 0~3 在线 |
| 10, 11 | 在线 - NFC | |
| 12 | `0xFF` 或 detected | 打印中会被改成 `filament_flag_detected` |
| 13 | NFC 掩码 | |
| 17 | ams | 重复 |
| **19** | **use_flag** | 使用中标志，抓包看这个 |
| **20** | **料位** | `read` 回显，`0xFF` 表示当前料位 |
| **21-24** | **meters** | float32 小端，本通道已用米数 |
| **25-26** | **pressure** | uint16 小端，压力值，`0xFFFF` = 无耗材 |
| 41 | 余量字符 | `get_filament_left_char()` |

抓包时最常看的四个：`use_flag` / `料位` / `meters` / `pressure`。

## 五、一次成功的进料时序（A1，2026-10-25 验证）

```
打印机                          AMS
  │  Dxx 03/00 read=01            │
  ├──────────────────────────────>│  内部 → send_out
  │                               │  吸合离合 0x01，电机正转 100%
  │  (周期性查询 use_flag/料位)    │  计米累加 ~0.05 m/s
  │<──────────────────────────────┤
  │                               │
  │  Dxx 09/A5 read=01            │  ← 挤出机已咬住，开始拉料
  ├──────────────────────────────>│  内部 → before_on_use
  │                               │  ★ 跟随送料泵：送 250ms / 停 350ms
  │                               │    平均 ≈21mm/s，略高于挤出机拉速
  │                               │
  │  Dxx 0F/FF read=01            │  ← 进入正式使用
  ├──────────────────────────────>│  内部 → on_use
  │                               │  交给缓冲微动按需补料
  │                               │
  │  (打印中周期性 0x0F/00、0x01)  │  ← ★ 不能把状态清掉
  │<──────────────────────────────┤     （v1.1.12 之前的坑）
  │                               │
  │  Dxx 09/3F read=01            │  ← 准备退料
  ├──────────────────────────────>│  内部 → before_pull_back
  │  Dxx 03/00 read=FF            │  ← 退料
  ├──────────────────────────────>│  内部 → pull_back，电机反转
  │                               │  超时 PULLBACK_TIMEOUT 秒后放弃
```

**验证成功的判据**（`/status` 的 `feed` 段）：

| 字段 | 期望 |
|---|---|
| `phase` | 依次出现 `before_on_use` → `on_use`，不再卡在 `none` |
| `follow` | `before_on_use` 期间在 `1/0` 之间跳（250/350ms） |
| `meters` | 送料 1 秒约 +0.05 米（不是几十米） |
| `clutch_mask` | 送料期间 `0x01`（A1 对应通道 0） |

## 六、怎么抓包

```bat
tools\mon485.bat 192.168.2.100 50
```

- 青色 = 打印机发来，绿色 = 我方应答，黄色 = ★电机动作，红色 = 丢帧告警
- 全部写 `tools\logs\mon485_*.log`
- 抓完 `tools\ana_log.bat` 压成一页看

设备端接口是 `GET /bus485raw?since=<seq>`，返回：

```
RX_TOTAL=25483 TX_TOTAL=15310 LAST_SEQ=40793
40794 454143 RX 13 3DC50DF10400030003FF003180
40795 454144 TX 60 3DD83C0E04...
```

`since` 只回新帧。**固件端只有 32 帧缓冲**，所以脚本要高频轮询 + 内层追平。

## 七、CRC

| | 多项式 | 初值 | 反转 |
|---|---|---|---|
| CRC8 | `0x39` | `0x66` | 否 |
| CRC16 | `0x1021` | `0x913D` | 否 |

初始化代码：`crc_8.reset(0x39, 0x66, 0, false, false)` / `crc_16.reset(0x1021, 0x913D, 0, false, false)`
（签名是 `reset(polynome, initial, xorout, refin, refout)`，**第一个参数是多项式**）。
实现见 `lib/CRC/`。
