# v1.1.11 —— 修复"送料到位后挤出机拉一点就停、报挤出失败"

## 现场现象

```
送料到位 → 挤出机拉动一点就停 → 打印机报「挤出失败」→ 电机退料重试
（不是反复进退，是一次就弹故障）
```

## 根因：计米单位错 1000 倍，导致打印机提前认为"料已送够"

抓包（`tools/新建 文本文档.txt`）看到我方 Dxx 应答里的 `meters` 字段：

| 时刻 | 事件 | 我方上报的 meters |
|---|---|---|
| 15:05:53 | 打印机发 `03/00/00` 送料 | 0 |
| **15:05:57** | **打印机发 `09/A5` before_on_use** | **141.1 米** |
| 15:06:02 | 打印机发 `07/00` stop_on_use（拉料失败） | 141.1 米 |
| 15:06:03 | 打印机发 `09/3F` 准备退料 | 141.1 米 |
| 15:06:29 | 第二次送料后 | **818.6 米** |

**送料只进行了 3.3 秒，却上报了 141 米**（真实应约 0.15 米）。

`src/AMCU.cpp` 原代码：

```cpp
uint32_t dt = now - s_last_drive_ms;              // 毫秒
float meters = (float)dt * FILAMENT_PUSH_M_PER_SEC;  // 0.05 = 米/秒
```

毫秒 × 米/秒 → 结果放大 **1000 倍**。50ms 被算成 2.5 米。

打印机靠 `meters` 判断「AMS 送了多少料」，看到 3 秒送了 141 米，自然认为早就到位，
于是提前发 `before_on_use` 让挤出机拉料 —— 实际耗材才走 150mm，拉不到就判挤出失败。
**（现场直觉"485 的消息给早了"完全正确。）**

修复：

```cpp
if (dt > 500) return;                                  // 卡顿后不要一次补一大段
float meters = ((float)dt / 1000.0f) * FILAMENT_PUSH_M_PER_SEC;
```

修正后：50ms → 2.5mm，3 秒 → 0.15 米，符合 AMS lite 实际送料速度（约 50mm/s）。

## 与 Tianshu 的对比（为什么它没这个问题）

| 项 | Tianshu | 本工程（v1.1.10 及更早） |
|---|---|---|
| 计米来源 | `AS5600_get_distance_E()` | 时间估算 `dt × 速度` |
| 实际实现 | **是随机数模拟**（正态分布 3~8mm/次，注释写明"生成模拟的距离数据，用于测试"） | 时间差 × 速度 |
| 单位 | 每次返回的就是"米" | `dt` 是毫秒却当秒用 → ×1000 |

Tianshu 的 AS5600 是假数据，但它**每次直接返回米**，所以不会有单位错；
我们改成时间估算时把毫秒当成了秒，才引入这个 1000 倍误差。

其余协议状态机（`process_motion_state_machine` / `send_for_Dxx` / `get_pressure_value`）
两边逐行对比**完全一致**，唯一差异是本工程补了 `now_filament_num < 16` 的越界保护。

## ⚠️ 刷完必须做一步

旧固件已经把错误的计米值写进了 flash（当前料位 818 米）。刷入后：

- 网页 →「换料动作」→ 点 **清零计米**（确认一次）

否则打印机按 `meters` 折算料盘余量，会认为料已用光。

## 验证方法

1. 网页日志应出现正常的 `送料开始` / `退料开始` / `退料结束`
2. 测试进料，观察 `/status` 的 `feed.meters`：
   - 送料 1 秒约 **+0.05 米**（50mm）
   - 若看到一秒涨几十米，说明又跑飞了
3. 打印机侧：`before_on_use` 不应再在送料开始 3 秒后就出现；
   正常应等耗材真正到达挤出机才发，随后进入 `07/7F`（on_use）

## 已知遗留

- **`on_use`（打印中）计米仍是估算**：`meters += time_used_ms / 300000`，且累计 10 秒
  （`meters_virtual_count < 10000`）后停止增长。打印长任务时这个值不会持续上涨。
  如果后续打印机报「耗材卡住/用尽」，需要再调这一段。
- **`before_on_use` 时立即停电机**：与 Tianshu 行为一致，本次未改。
  若修复计米后仍出现"拉一点就停"，下一步应改为「`before_on_use` 期间低速跟随送料」。
- 堵转阈值 `stall_ma` 仍为 0（只显示不保护）。
