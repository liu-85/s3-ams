# v1.1.13 —— 修「当前固件仅支持 AMS / AMS 2 Pro / AMS HT」弹窗

## 现象

打印机频繁弹窗：

```
当前固件仅支持 AMS / AMS 2 Pro / AMS HT，最多可连接 4 台，
请务必先移除所有 AMS，再重新插入上述支持的设备。
[0500-40A5 173125]
```

同一块板子在 `esp32s3-485` 那版固件上**不弹窗**（只在 HMS 里留一条提醒），
说明不是硬件问题，是**上报内容**的问题。

---

## 根因：上报的 AMS 固件版本号是编造的

打印机在长包 `0x103` 里问"你的固件版本是多少"，我们回的 21 字节是：

```
[0..3]  版本号 uint32 小端
[4..8]  型号代号 "AMS08"
[9..19] 补 0
[20]    台号
```

Tianshu 原版（我们直接移植过来的）版本号写的是：

```cpp
{0x00, 0x00, 0x00, 0x5A, ...}   // = 90.00.00.00  ← 编造的，不存在这个 AMS 固件
```

旧打印机固件不校验，能混过去。**新固件会拿这个号去跟白名单比对**，对不上就把你
这台判成"不认识的 AMS 设备"，于是弹出上面那个对话框。

两个独立项目都踩过并修过同一个坑：

| 项目 | 版本号 | 结果 |
|---|---|---|
| Tianshu / 本工程 v1.1.12 及更早 | `00 00 00 5A` = **90.00.00.00** | 新版固件弹窗 |
| `esp32s3-485` | `31 06 00 00` = **00.00.06.49** | 不弹窗（真机抓包值） |
| `BMCU-U` / BMCU-X | `57 06 00 01` = **01.00.06.87** | A1 固件 01.08.01.00 验证通过 |

`esp32s3-485/main/comm_485.c` 里当时就写了结论：

> 旧版照 Tianshu 发 `00 00 00 5A`（90.00.00.00）+ "AMS08"。Tianshu 在旧版打印机固件上
> 能混过去，但**新版打印机会拿这个版本号跟自己的白名单比** —— 90.00.00.00 显然不在里面。

---

## 修复

### 1. 默认改成 01.00.06.87

```cpp
#define AMS_FW_VER_DEFAULT  0x01000657u   /* 01.00.06.87 */

// 包体改成运行时拼装，不再用写死的数组
ver_pkt[0] = (v      ) & 0xFF;   // 0x57
ver_pkt[1] = (v >>  8) & 0xFF;   // 0x06
ver_pkt[2] = (v >> 16) & 0xFF;   // 0x00
ver_pkt[3] = (v >> 24) & 0xFF;   // 0x01
memcpy(ver_pkt + 4, "AMS08", 5);
ver_pkt[20] = AMS_num;
```

### 2. 做成可配置，不用重编译

不同打印机固件的白名单不一样，所以网页「和打印机的通信方式」里加了一个下拉框：

| 选项 | 值 | 说明 |
|---|---|---|
| 01.00.06.87 | `16778839` | **默认**，A1 FW 01.08.01.00 验证过 |
| 00.00.06.49 | `1585` | BMCU370 真机抓包 |
| 90.00.00.00 | `1509949440` | Tianshu 原值，会弹窗，留着只为对照 |

- 存 NVS 命名空间 `s3ams-bus`，键 `ver`，重启不丢
- **立即生效**（下一次 `0x103` 查询就用新值），不用重启
- `/status` 新增 `ams_ver`（字符串）和 `ams_ver_raw`（整数）回显
- 新接口 `POST /ams_ver_set {"raw": <uint32>}`

## 验证方法

1. 网页 OTA 刷 `firmware.bin`，确认版本号变成 `1.1.13-s3ams`
2. 打开网页「和打印机的通信方式」，看「上报版本」应为 `01.00.06.87 (0x01000657)`
3. **让打印机重新识别**：拔插 485 线，或重启打印机（打印机的总线枚举只在上电那一小会儿做）
4. 观察是否还弹窗

如果换了版本号还弹，按这个顺序排查：

| 检查项 | 说明 |
|---|---|
| 型号代号 | 必须是 `"AMS08"`（AMS / AMS 2 Pro / AMS HT 这条线）。写成 `AMS_F102` 会被当成 AMS Lite，地址 `0x0700` 与身份矛盾 |
| 源地址 | 恒为 `0x0700`，**绝不跟随打印机**。按 `0x1200` 答会报"AMS/AMS Lite 连接方式异常" |
| AMS 台数 | 本板 8 通道 = **2 台** AMS。若注册了 4 台，打印机会看到 16 个槽但只有 8 个是真的 |
| 注册包身份 | 29 字节里 [7..26] 那 20 字节是**型号指纹**，必须和真机一致，逐台不能改 |

## 抓包对照

```
# 打印机问版本（长帧 0x103）
TX 3D C0 .. 05 .. 03 01 00 00 ...
# 我方应答 21 字节
   v1.1.12: 00 00 00 5A 41 4D 53 30 38 00 ... 00 00    ← 90.00.00.00  ✗
   v1.1.13: 57 06 00 01 41 4D 53 30 38 00 ... 00 00    ← 01.00.06.87  ✓
```

用 `tools/mon485.bat` 抓，看 `TX` 里 `len` 对应的长帧即可。

## 已知遗留

- 只改了版本号，**型号代号仍是 `AMS08`**。如果将来要用 AMS Lite 线（`0x1200` +
  `AMS_F102` + `00.00.08.15`），三处必须同时改，否则地址和身份打架。
- `AMS_COUNT` 默认 4，但本板只有 8 通道（= 2 台）。多出来的 2 台会报"在线"但槽位
  没有物理通道。暂未改默认值（怕影响已有配置），需要时手动改 NVS。
