## 二、网络配置补齐 MQTT 设置（本次重点）

**问题**：模板是「静态控制台」，MQTT 表单原本靠 `GET /get_mqtt_info` **动态生成**。
没有设备（或固件没这个接口）时请求失败 → 表单不渲染 → 页面上**只剩一个「保存并连接」按钮**，
看不到输入框。

**修复**：

1. **表单改成静态字段**（写在 `index.html` 里），不再依赖设备接口，永远显示：
   - 打印机 IP（`mq_host`）
   - **访问码（8 位）**（`mq_pass`，密码框，留空 = 不修改）
   - 序列号（`mq_serial`）
   - 用户名（`mq_user`，默认 `bblp`）
   - 端口（`mq_port`，默认 `8883`）
   - 客户端 ID（`mq_cid`，留空自动生成）
2. `loadMqttForm()` 改为**只填值、不重建 DOM**：有 `/get_mqtt_info` 就回填已保存的值，
   没有也保留静态字段。
3. 固件新增接口：
   - `GET  /get_mqtt_info` → 回传已保存参数（**不回传访问码**）
   - `POST /mqtt_connect` → 保存参数到 **NVS（命名空间 `s3ams-mqtt`）**，掉电保留
4. `/status` 的 `mqtt_configured` 改为按「是否已保存过」动态返回。

> ⚠️ **本固件走 RS-485 直连打印机（BambuBus）**，MQTT 参数**只保存备用**，
> **不会真的去连 MQTT Broker**。页面说明里已写明。

## 三、顺带补齐的接口（避免 404 弹「请求失败」）

模板控制台会调用一批旧固件没有的接口，本次按能力分别处理：

| 接口 | 处理 |
|---|---|
| `POST /stop`（紧急停止） | ✅ **真实现**：取消点动 + 停电机 + 断全部离合 |
| `POST /ap_set`（开关配置热点） | ✅ **真实现**：调用 `wifi_start_ap()` / `wifi_stop_ap()` |
| `GET /get_mqtt_info`、`POST /mqtt_connect` | ✅ **真实现**：NVS 保存/回读 |
| `GET /boot_clear` | ⚠️ 回 `{ok:false,"本固件不支持"}`（固件不统计启动次数） |
| `POST /creep_set` | ⚠️ 同上（本固件无蠕动参数） |
| `POST /assist_test` | ⚠️ 同上 |
| `POST /extruder_src_set` | ⚠️ 同上（本固件固定 GPIO1 到位信号） |

新增 `handle_unsupported()`：统一回 `{"ok":false,"info":"本固件（RS-485 直连）不支持该操作"}`，
比原来的 404 更明确。

## 六、已知限制

- **MQTT 不实际连接**：本固件是 RS-485 直连方案，MQTT 参数仅保存。
- 「通道设置」的 `access_set`、「辅助送料」「退料参数」「换料温度」的保存按钮，
  后端仍是 `handle_ok` 占位（与本版前一致，未在本次范围内实现）。
- 蠕动送料参数、辅助送料自检、到位信号来源切换：本固件无对应功能，点保存会提示「不支持」。
