## 现场症状

- 通道 1（料盘位 1）微动在 WEB 上会跟着手动触发变化
- 通道 2~4（料盘位 2/3/4）无论怎么按，状态都不变（一直显示"触发"）
- v1.1.14 测试微动时是正常的

在没有实测数据前改逻辑，只会在错误的方向上打补丁。

## 新增：`/sensor_raw` 诊断接口

浏览器直接打开：

```
http://192.168.2.100/sensor_raw
```

返回示例：

```json
{
  "mode": "digital",
  "mask": 15,
  "pins": [1, 2, 9, 8, 10, 11, 12, 13],
  "raw":  [1, 0, 0, 0, 1, 1, 1, 1],
  "trig": [[0,0], [0,1], [0,1], [0,1]]
}
```

| 字段 | 含义 |
|---|---|
| `pins` | 8 只微动对应的 GPIO（前 4 = 各通道开始位，后 4 = 各通道停止位） |
| `raw` | **原始 digitalRead 电平**：`1`=HIGH 松开，`0`=LOW 压下 |
| `trig` | 去抖后的 `[停止位, 开始位]`（前 4 个通道） |
| `mask` | 缓冲送料启用掩码，`15`(0x0F) = 前 4 路都开 |

### 判读表

| 现象 | 结论 |
|---|---|
| 按下时 `raw` 从 `1` → `0` | 硬件正常，问题在软件（掩码/映射/去抖） |
| 按下时 `raw` 一直是 `1` | 微动没接通 / GND 没共地 / 接的是常开端但线断了 |
| `raw` 一直是 `0`（松开也不回 1） | 引脚被拉死：**接了常闭(NC)触点** / 对地短路 / 引脚被占用 |
| `raw` 会变但 `trig` 不变 | 去抖或掩码问题 |

**本次现场最可能**：通道 2~4 一直显示"触发"（= LOW），说明 `raw` 恒 `0`
→ 这几只微动很可能接的是**常闭（NC）触点**，而通道 1 接的是常开（NO）。
两者电平极性相反，软件只按一种极性解析，所以只有一路能正常变化。

若确认是常闭，两种解法（任选其一）：
1. **换线**：把这几只微动从 NC 端改接到 NO 端（推荐，与其他通道统一）
2. **软件**：给每个通道单独配极性（我可以加 `sensor_polarity_mask`）

## 顺带修复：缓冲送料开关关不掉

前端 `app.js` 发的字段名是 **`enabled`**：

```js
post('/sensor_set', { channel: ch, func: ..., enabled: en ? 0 : 1 })
```

后端 `handle_sensor_set()` 找的却是 **`"enable"`**：

```cpp
int eidx = body.indexOf("\"enable\"");
```

`"enable"`（带引号）在 `"enabled"` 里**匹配不上**（`e` 后面是 `d` 不是 `"`），
于是 `eidx` 恒为 `-1`、`enable` 恒为 `-1`、`enable != 0` 恒为 `true`
→ 缓冲送料开关**只能开、关不掉**。

v1.1.24 两种写法都认（`"enabled"` 优先）。
