> 版本：`1.1.27-s3ams`
> 日期：2026-10-31
> 主题：**退料阶段整段禁止缓冲补料**，并把送料超时做成网页可调

## 一、修了什么：退料过程中又把料送进挤出机

### 现场现象

> "打印结束、退料过程中应该是触发了开始微动，又送料进挤出机了"

### 根因：`statu == 0x09` 有两种相反的含义

`is_channel_active_recently()` 判断"该通道最近是否被打印机当成在用"，只看
`statu` 位掩码：

```cpp
const bool in_use = (s == 0x03) || (s == 0x07) || (s == 0x09) || (s == 0x0F);
```

但 **`0x09` 在 485 协议里是歧义的**，必须结合 `motion_flag` 才能分辨：

| statu | motion_flag | 真实含义 | 该送料吗 |
|---|---|---|---|
| `0x09` | `0xA5` | `before_on_use`（准备使用） | ✅ 该送 |
| `0x09` | `0x3F` | `before_pull_back`（**准备退料**） | ❌ **绝不能送** |

只看到 `0x09` 就当"在用"，于是：

```
打印机发 0x09/0x3F（准备退料）
  → is_channel_active_recently() 返回 true
  → check_buffer_status() 准入放行
  → 料刚退走，缓冲器空了，开始微动触发
  → AMCU_drive_channel(FEED)
  → 刚退出来的料又被塞回挤出机 ❌
```

而且 `if (is_need_pull_back) return;` 也挡不住 —— 退料 3 秒超时后
`is_need_pull_back` 就被清了，但打印机可能还在退料流程里。

### 修法（两道）

**① `is_channel_active_recently()` 排除退料阶段**

```cpp
if (ext->motion == before_pull_back || ext->motion == pull_back) return false;
```

**② `check_buffer_status()` 显式让出**

新增 `is_channel_pulling_back(num)`，在准入判断之前：

```cpp
if (is_channel_pulling_back(cur)) return;
```

判据落到 `motion` 上，而不是那个 3 秒就失效的布尔量。

**③ `buffer_feed_holds_motor()` 同步排除**

退料阶段也不允许缓冲逻辑压着电机不让停（否则退料会被缓冲送料顶掉）。

## 二、新增：缓冲送料超时可在网页设置

### 要解决的问题

> "增加一个缓冲器打印过程中的开始微动触发后，设置一个超时，
> 防止停止微动没有触发一直送料"

打印中如果「开始微动」一直压着（停止微动不触发 / 微动接反卡在触发态），
缓冲逻辑会一直送料：电机空转发热、电源纹波变大（会拖累 485），
料还会被顶进挤出机。

### 位置

「参数设置」页 → **自动送料** 卡片 → 第二行「秒 超时」。

### 接口

```http
POST /feed_timeout_set   {"sec": 30}
→ {"ok":true,"sec":30,"info":"缓冲送料超时已保存"}
```

| 项 | 值 |
|---|---|
| 默认 | **30 秒** |
| 范围 | **5~120 秒** |
| 存储 | NVS `s3ams-feed` 的 `feed_timeout`（与 PWM 同命名空间） |
| 生效 | 立即，重启不丢 |

### 为什么默认 30 秒

按 2026-10-31 的实测电流日志，**正常补料一次持续 7~15 秒**
（`时长=7067/8096/8311/8797/15092/15104/15111ms`）。
30 秒留了约一倍余量，不会误杀正常补料。

**到点后的行为**：强制停电机 + 清决策 + 打日志

```
缓冲送料超时强制停：通道4 连续送料超过 30 秒（微动可能卡在触发态，
检查该路微动是否常闭接反/短接到 GND）
```

之后要等**微动松开**（`start_trig` 变 false）才会重新计时 ——
不是"每 30 秒重试一次"，避免卡死时反复启动。

### 调参建议

| 现象 | 调整 |
|---|---|
| 正常补料被中途打断（料没送够就停） | **调大**（40~60） |
| 卡住后要等很久才停 | **调小**（10~15） |

## 三、关于你贴的这组电流数据 —— 有个更重要的发现

### 数据本身有个矛盾

```
进料 PWM=90% 时长=15092ms 启动峰值=435mA 稳态均值=2mA 稳态峰值=60mA 全程最大=485mA
进料 PWM=90% 时长=15111ms 启动峰值=140mA 稳态均值=4mA 稳态峰值=225mA 全程最大=1810mA
```

**稳态均值只有 1~5mA**，但电机被驱动了 15 秒。

按 200mΩ 采样电阻（200mV/A）折算，1~5mA 对应 **0.2~1mV** —— 这就是 ADC 的零点噪声水平。
**正常运转的小直流电机，空载也有 50~200mA。所以这 15 秒里电机实际上没转。**

而 `启动峰值=140~1640mA`、`全程最大=780~1810mA` 又说明**确实有电流出现过**。
两者放在一起，说明电机是**脉冲式工作**：启动一下就停，过一会儿再启动。

### 结论：**这组数据不能用来定堵转阈值**

如果按 `稳态均值` 定阈值（比如 50mA），正常打印会立刻误跳；
如果按 `全程最大` 定（1800mA），那等于没有保护。

### 建议的下一步（不用刷机，v1.1.26 已有电流统计）

在 WEB「硬件调试」里做一次**受控点动**：

1. 选一个**没装料**的通道（空转，阻力最小）
2. 点动进料 **3 秒**，看日志的「电流统计」
3. 再选一个**装料**的通道，点动 3 秒，对比

判读：

| 点动结果 | 说明 |
|---|---|
| 稳态均值 **几百 mA** | 电流采样正常 → 打印中那些 1~5mA 说明"缓冲送料在空转/没真正驱动电机"，问题在送料逻辑不在采样 |
| 稳态均值仍是 **1~5mA** | 电流采样本身有问题（ISEN 采样点、ADC 校准、或 PWM 关断期采样），阈值先别设，保持 `0` |

**所以现在请保持 `堵转阈值 = 0`（只显示不保护）**，等 v1.1.27 修掉"退料又送料"后
再采一轮数据 —— 很可能那批 15 秒的异常送料就是被这个 bug 拖出来的
（退料/送料互抢导致电机反复启停，电流才这么碎）。
