# v1.1.29 —— 退料静默期 + WS2812 状态灯 + 送料超时锁存 + 双微动失效保护

> 版本：`1.1.29-s3ams`
> 日期：2026-10-31
> 主题：**把"退料时又送料"彻底堵死；给板载 RGB 灯一套完整灯语；两个超时都改成真正"停住"**

---

## 一、这版解决的 4 件事

| # | 现场问题 | 本版做法 |
|---|---|---|
| 1 | 打印结束退料时，跟随挤出机拉出耗材 → 触发送料微动 → **又把料送进挤出机** | 退料结束后 **10 秒静默期**，缓冲送料完全不理微动 |
| 2 | 板载 WS2812 灯不亮 / 颜色固定不变 | 全新 `rgb_led` 模块，6 种状态灯语 + 打印时按耗材颜色呼吸 |
| 3 | 「送料超时」到时停一下，但微动还压着 → **下一秒又开始送**，等于没停 | 超时后**锁存**，必须"微动松开再压下"才恢复送料 |
| 4 | 两个微动都不触发（断线/卡死）→ 一直送料 | 新增**双微动失效保护**，超时停机，时长 WEB 可调 |

另外顺手修了两个让**电流数据不可信**的统计 bug（见第四节），这是上一版"稳态均值恒 0"的真正原因。

## 二、退料静默期（10 秒）

### 现场

```
电流统计: 退料 PWM=100% 时长=2912ms 启动峰值=260mA ...
退料结束: 料位1 已反转 3 秒，停电机
电流统计: 进料 PWM=90%  时长=2356ms 启动峰值=55mA  ...   ← ★ 退料刚结束就进料
```

退料刚完，**紧接着一条进料**。这就是"料被拉出去又被顶回来"。

### 为什么 v1.1.27 没堵住

v1.1.27 的判据是 `is_channel_pulling_back()`（看 `ext->motion` 是不是
`before_pull_back` / `pull_back`）。这层判据是对的，但**有窗口漏掉**：

- `is_need_pull_back` 只有 **3 秒**时效，退料超时后它被清掉
- 而打印机的退料流程可能还在跑，`motion` 又可能被后续包改写
- 退料段一过，`statu` 就回到 `0x09`，而此时 `0xA5`（该送料）与 `0x3F`
  （正在退料）**无法区分**

结果：退料尾段有几十~几百毫秒的"状态空窗"，微动正好在这时被料顶到 → 判成该补料。

### 做法

```cpp
#define PULLBACK_SILENCE_MS 10000
static uint32_t s_pullback_end_ms = 0;

/* check_buffer_status() 最前面 */
if (s_pullback_end_ms != 0 && (millis() - s_pullback_end_ms) < PULLBACK_SILENCE_MS)
    return;      /* 退料后 10 秒内，缓冲送料完全不管微动 */
```

`s_pullback_end_ms` 在退料流程结束处打点（用 0 作"未退料"哨兵，所以置 1）。

**为什么是 10 秒**：正常一次退料 2~4 秒，10 秒足够覆盖"退料 + 打印机回抽 +
用户手拽"全过程。如果你发现退料后手动补料被挡住太久，可以把这个宏调小
（`src/AMCU.cpp` 顶部，5~8 秒都合理）。

> 副作用（可接受）：退料后 10 秒内手动触发送料微动不会自动送料。
> 这是**故意的** —— 退料期间任何自动送料都是风险。

## 三、WS2812 状态灯

### 硬件

板载单颗 WS2812，数据脚 `BOARD_PIN_LED`（**GPIO42**）。
驱动用 Arduino-ESP32 core 自带的 `neopixelWrite()`（走 RMT 硬件），
**不需要装 FastLED / Adafruit_NeoPixel**。

### 原来为什么完全没效果

`set_led_state()` 里是 `gpio_set_level()` —— 那对 WS2812 是无效的
（WS2812 要 800kHz 编码，不是电平）。而且 `init_io_pins()` 还把 GPIO42
配成了普通输出，等于把 WS2812 的数据线拉死了。本版两处都改掉。

### 灯语表

| 状态 | 颜色 | 效果 | 优先级 |
|---|---|---|---|
| 故障（堵转 / 双微动失效） | **红** | 快闪 200ms/200ms | 1（最高） |
| 退料中 | **橙** | 呼吸 | 2 |
| 临时提示（`set_led_state`） | 红/绿/蓝 | 常亮 800ms | 3 |
| 打印中 | **当前通道的耗材颜色** | 呼吸 | 4 |
| 就绪空闲 | **绿** | 低亮常亮 | 5 |
| 等 WiFi / 未联网 | **黄** | 慢闪 1s/1s | — |

打印中的颜色取自 WEB「通道设置」里给该通道选的颜色
（`web_get_channel_color()` → NVS `s3ams-access`）。没设过就是默认绿
`0x22CC66`。

呼吸节奏：32 拍一个来回 ≈ **3.2 秒**，亮度上限 `LED_MASTER_BRIGHT = 0x60`
（约 38%，夜里不刺眼）。

### 为什么刷新要限流

`neopixelWrite()` 每次约 **30us**（24bit × 1.25us）。485 是 1.2288Mbps
≈ 154 字节/ms，30us 会吃掉 **~3.7 字节**。

所以 `rgb_led_tick()` 内部：

- 限流到 **100ms 一次**（10fps，呼吸够顺）
- **颜色没变就不写**（避免每 100ms 白白打断一次 485）

这样主循环单次最多被打断 30us，不会把 485 帧撕坏。

## 四、「送料超时」改成真正的锁存

### 原来的问题

```
触发开始微动 → 送料 → 到 30 秒超时 → 停电机 → 清 decision
                                    ↓
              微动还压着 → 下一轮 start_trig 仍是 true → 重新计时 → 又送 30 秒
```

表现成"每 30 秒抖一下又送一截"，**并没有真的停**。

### 现在

```cpp
static bool s_feed_latched[BOARD_CHANNEL_COUNT];   /* 超时锁存 */
static bool s_start_trig_last[BOARD_CHANNEL_COUNT];

const bool start_rising = start_trig && !s_start_trig_last[channel];
s_start_trig_last[channel] = start_trig;

if (s_feed_latched[channel]) {
    if (start_rising) {
        s_feed_latched[channel] = false;      /* 微动松开再压下 → 解除 */
        log_i("缓冲送料：通道%d 微动重新触发，恢复送料", channel + 1);
    } else {
        return;                                /* 还压着 → 就是不送 */
    }
}
```

**这就是你描述的语义**：

> 触发开始微动送料后如果停止微动没有触发，超过 N 秒停止送料，
> **再触发开始微动了**就继续送料。

N 在 WEB「参数设置 → 自动送料 → 送料超时」调，默认 **30 秒**，范围 5~120。

## 五、双微动失效保护（新增）

### 需求

> 在打印过程中如果两个都不触发，超过多少秒就停机保护。

### 实现

在 `AMCU_buffer_assist_feed()` 里：

```cpp
if (!start_trig && !stop_trig) {
    if (s_idle_since[channel] == 0) s_idle_since[channel] = now;
    const uint32_t idle_ms = settings_get_idle_timeout() * 1000u;
    if (idle_ms > 0 && (now - s_idle_since[channel]) > idle_ms) {
        AMCU_drive_stop();
        s_buffer_feed_decision[channel] = 0;
        ... 限流日志（30 秒一条）
        return;
    }
} else {
    s_idle_since[channel] = 0;
}
```

- 默认 **60 秒**，范围 **0~600**，**填 0 = 关闭**
- WEB：参数设置 → 自动送料 → **双微动失效保护**
- 日志（30 秒限流一条）：
  ```
  缓冲器双微动失效：通道4 开始位/停止位均未触发超过 60 秒，已停机保护（检查该路微动接线）
  ```

**为什么给 60 秒这么长**：缓冲器半满时"两个都不触发"是**正常中间态**
（料在两个微动之间）。给太短会误停。真断线/卡死的话 60 秒内必然暴露，
而 60 秒的持续送料量还不至于把料顶穿挤出机。

### 关于「发给打印机暂停信号」

**做不到，本版没做。** 原因：

1. 本项目 485 实现只覆盖了 BambuBus 的**状态上报 + 少数查询应答**
   （`0x402` / `0x103` / `0x06`），没有实现任何"控制打印机"的命令
2. 厂商的暂停/停止命令**未公开**，协议里发错一个字节的后果是打印机报
   通信异常甚至进入保护态 —— 比"料多送一点"严重得多
3. 本机是 **AMS 从机**，协议上它是"被查询"的一方，主动下发控制命令
   不在从机职责内

所以只做**本地停机保护**：停电机 + 释放离合 + 红灯快闪 + 日志报警。
真要暂停，请在打印机屏幕上点，或从 Bambu Studio / 手机端暂停。

## 六、顺手修的两个电流统计 bug（重要）

上一版你贴的数据里，`稳态均值` 全是 **0 / 1~5mA**，`时长` 全是 **780~812ms**。
当时看着像"电流采样坏了"，其实**是统计代码的两个 bug**：

### Bug 1：启动段定义太长

```cpp
#define MOTOR_PROFILE_START_MS 800    /* 旧 */
```

缓冲送料每次只转 **780~812ms** —— 整段都被划进"启动段"，
**稳态段一个采样点都没有**，均值当然是 0。

→ 改成 **300ms**（真实的起动尖峰只有 50~200ms）。

### Bug 2：每次换速都重置统计

缓冲微动用 `FEED_PWM`（90%），状态机送料用 `MOTOR_SPEED_485_FEED`（100%），
两边每几百毫秒交替一次 → `motor_set_dir_speed()` 每次都判定"变了" →
`motor_profile_start()` 重置 → 时长永远停在 ~800ms。

→ 改成**只在换向时重启统计**，同方向换速只更新 PWM 记录：

```cpp
if (!same_dir || s_dir_started_us == 0) {
    motor_profile_start(dir, speed_pct);
} else if (s_prof.active) {
    s_prof.pct = speed_pct;      /* 同方向换速：继续累计 */
}
```

### 所以：**堵转阈值这版先别设**

`CURRENT_DEFAULT_STALL_MA = 0`（只显示不保护）。请刷 v1.1.29 后重采：

1. WEB「硬件调试」→ 选**没装料**的通道，点动进料 3 秒 → 记 `稳态均值`
2. 选**装料**通道，点动 3 秒 → 记 `稳态均值`
3. 手动捏住耗材堵转 3 秒 → 记 `稳态峰值`

判读：

| 现象 | 结论 |
|---|---|
| 稳态均值 **几百 mA**（空载 100~300、带料 300~800 属正常） | 采样正常 → 阈值取「带料稳态 × 2」，约 **700~1200** |
| 稳态均值仍是 **0 / 个位数** | 采样链路有问题（ISEN 没接 / R 值不对 / ADC 通道错）→ 别设阈值 |

## 八、刷完怎么验证

### ① 退料不再送料

打印一个**多色**模型，让它跑到换料 → 看退料结束后的日志：

**不应该**再出现"退料结束后紧跟一条进料统计"。

### ② 灯

| 时机 | 应该看到 |
|---|---|
| 上电 | 蓝闪 → 连上 WiFi 后绿低亮 |
| 打印中 | 当前耗材颜色呼吸 |
| 换料退料 | 橙呼吸 |
| 堵转 / 双微动失效 | 红快闪 |

### ③ 送料超时锁存

把「送料超时」临时改成 **5 秒**，打印中把送料微动**按住不放**：

- 5 秒后电机停 → **就一直停着**（不再周期性抖一下）
- 松开再按下 → 日志出现「微动重新触发，恢复送料」→ 电机转

### ④ 双微动失效保护

把「双微动失效保护」临时改成 **10 秒**，把某一路**两个微动都拔掉**
（或都按住让它俩都不触发），10 秒后：

```
缓冲器双微动失效：通道N 开始位/停止位均未触发超过 10 秒，已停机保护
```

同时红灯快闪。测完记得改回 **60**。
